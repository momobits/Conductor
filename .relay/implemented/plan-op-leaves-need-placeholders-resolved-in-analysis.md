# `conductor plan` SYSTEM_PROMPT extracts resolved decisions before atomic steps

## Summary

*Resolved: 2026-05-14*

- **Problem:** `conductor plan` emitted `[need: ...]` placeholders for design decisions the immediately-preceding `## Analysis` section had already settled, eroding the analyze→plan pipeline's leverage. Dogfood T1-1 caught three of these on the first card (`2026-05-12-health-check-endpoint`); the downstream `review` op independently flagged the same gap as the plan's most significant deficiency. Root cause was structural: `src/engine/ops/plan.ts:22-42` SYSTEM_PROMPT had no "extract resolved decisions first" pass, and the `[need:]` instruction provided no counter-pressure when the model defensively over-applied the placeholder.
- **Resolution:** Restructured `SYSTEM_PROMPT` to require a `### Resolved decisions from analysis` preamble (Markdown H3) before the atomic-step plan. Each preamble bullet names a decision the analysis settled, with a short evidence quote drawn from the `--- Analysis ---` block in the user message. The `[need:]` rule was tightened with a defensive scan-first clause: "`[need:]` is ONLY valid for items not in the Resolved decisions preamble. Before writing any `[need:]`, scan the `--- Analysis ---` block in the user message; a `[need:]` for a decision the analysis already resolved is a defect." Strategy A (preamble enumeration) + Strategy B (scan-first defensive clause) layered into one prompt — the two failure modes are independent, so layering closes both.

## Caveats

- **Heading-level invariant: preamble MUST use H3, not H2.** `appendSection` wraps the model's output under a `## Implementation Plan` H2 header. If the model emits the preamble at H2, the result is two sibling H2 sections inside the card body, and `extractSection(card.body, 'Implementation Plan')` (used by `src/engine/ops/review.ts:41`) returns the empty content between them, breaking review. H3 keeps the preamble nested under the Implementation Plan section so downstream `extractSection` still returns the full plan body. The SYSTEM_PROMPT instruction names H3 explicitly and tests 6+7 assert H3 presence. The `extractSection` regex is `/\n##\s+/` — verified to match `\n## ` but NOT `\n### `.
- **`(none)` empty-analysis branch is uncovered by tests.** When the analysis settled nothing concrete, the SYSTEM_PROMPT instructs the model to write `(none)` under the preamble header so the structural section is always present. No regression test exercises this path — the prompt instruction is short and the failure mode is graceful (model emits `### Resolved decisions from analysis\n(none)\n` and downstream extractSection still returns the full body). Acceptable LOW advisory item from the adversarial review; defer test addition until dogfood signal warrants.
- **Re-running plan duplicates the Implementation Plan section.** `appendSection` always appends — no replace-or-noop logic. Theoretical concern only; no current call site re-runs plan on a card with an existing Implementation Plan section (the autonomy loop short-circuits on the populated section). Out of scope for this run; documented in the Analysis Related Work finding 3.
- **Pattern precedent for n=2 ops adopting "settle resolved context first."** Phase 12.1 established a HEAD-of-userPrompt context-injection pattern in `discover.ts` (operator-context layer). This phase introduces a required-output-preamble pattern in `plan.ts` (model-output layer). Both instances of the broader "settle resolved context first" principle. If a third op adopts it (natural next candidate: `review.ts` requiring a preamble that quotes the plan's `[need:]` items it accepted), filing an ADR is warranted at n=3. Not yet warranted at n=2.
