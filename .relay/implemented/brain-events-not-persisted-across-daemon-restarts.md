# `BrainLogWriter` persists conductor-* events to `.conductor/brain.log.jsonl`

## Summary

*Resolved: 2026-05-14*

- **Problem:** The daemon's `EventBus` published four `conductor-*` event kinds (`conductor-iteration`, `conductor-decision`, `conductor-halt`, `conductor-status`) to in-memory subscribers (SSE fan-out) but wrote nothing to disk. `src/daemon/event_bus.ts:5` explicitly stated "Events are not persisted anywhere — that's the JSONL run log's job (per spec § 14)." When the daemon stopped, brain history was lost; post-hoc diagnosis of overnight halts was impossible (T4-1). For a tool whose core proposition is autonomous AI driving the pipeline, this was a meaningful auditability gap.
- **Resolution:** Added a `BrainLogWriter` (`src/daemon/brain_log.ts`) that subscribes to the bus once at daemon startup, filters `kind.startsWith('conductor-')`, and appends one JSONL row per event to `.conductor/brain.log.jsonl`. The writer uses lazy mkdir + serialized `pending` Promise chain (no `WriteStream`, no ring buffer — `publish()` stays O(1) by chaining async work outside the publish stack) with a fail-once-then-quiet error guard (first write failure logs via `console.error`, subsequent failures silently swallowed to avoid spam during persistent disk-full). `pruneBrainLog` is a free function applying `pruneRuns`-equivalent union retention semantics (keep_last_n OR within keep_days) adapted to line-scope: parses per-row `ts` field; `keepDays=0` yields `cutoff=Infinity` matching the runlog precedent (time-window disabled, defers to keep_last_n). Wired in `startDaemon()` after bus creation and before `attachMcpServer`, with `try { await brainLog.close(); } finally { bus.close(); }` in shutdown so listener cleanup is structurally enforced even if drain throws. Dedicated `brain_log: { keep_days: 30, keep_last_n: 200 }` config block in `ProjectConfigSchema` parallel to `run_log` — `.default({})` so existing YAML configs cannot break. Doc comment at `event_bus.ts:5` updated to qualified persistence claim. Phase plan was the 5-agent /relay-superplan synthesis with Test-Driven as the base; adversarial review caught two MEDIUM defects (cutoff semantic flipped from `-Infinity` to `Infinity` to match `pruneRuns`; removed an `if (this.closed) return;` early-exit in `appendLine` that would have broken close-drain semantics and silently lost pre-close-scheduled events).

## Caveats

- **Lifecycle invariant: `writer.close()` MUST run BEFORE `bus.close()`.** Encoded in `index.ts:shutdown` via `try { await brainLog.close(); } finally { bus.close(); }`. The writer's `close()` unsubscribes from the bus first, then `await this.pending` drains any in-flight appendFile chain. If a future shutdown refactor changes this order, the `pending` chain might race with `bus.close()` clearing listeners — although in practice each chain link wraps appendFile in try/catch and swallows errors, so the drain is robust even under inverted ordering.
- **DO NOT add `if (this.closed) return;` to `appendLine`.** A 5-line `NOTE:` comment in the source explains this is the close-drain invariant. The `closed` flag guards `onEvent` (upstream of scheduling) so no NEW events are scheduled after close. But pre-close-scheduled lines must still write — adding the early-exit to `appendLine` would short-circuit the drain and silently drop those events. The adversarial review caught this as MEDIUM-2; Test #4 (close drains in-flight writes) explicitly guards it.
- **`pruneBrainLog` keepDays=0 matches `pruneRuns` semantic.** `cutoff = opts.keepDays > 0 ? ... : Infinity;` — when keepDays=0, the time-window keep-set is empty and retention defers to keepLastN. This matches the runlog precedent at `src/agent/runlog_store.ts:50`. An earlier draft had `-Infinity` (would have kept everything); caught and fixed during adversarial review (MEDIUM-1).
- **No fsync.** Same trade-off as `RunLogWriter`: ~last KB may be lost on hard crash. Acceptable for audit purposes. If durability ever matters more (e.g., regulated-audit context), add `fsync` to the writer's close drain in a follow-up. The append-only JSONL format is tolerant of truncated last lines — JSON.parse failure on the malformed tail can be skipped by readers (`pruneBrainLog` already does this).
- **Filter scope is forward-compatible.** `kind.startsWith('conductor-')` matches the current 4 kinds and any future `conductor-X` event type added to `DaemonEvent`. The default branch in `toRecord` handles unknown kinds by recording `{ ts, kind }` (no payload) so the writer doesn't crash on schema additions.
- **Dedicated config block, not reused `run_log.*` keys.** The 5-agent superplan synthesis recommended dedicated (over Minimal's reuse) for independence — users tuning brain-log retention (e.g., longer for audit) without affecting run-log retention is a clean separation. `.default({})` ensures pre-existing configs continue to work; tests/config/schema-phase14.test.ts pins this.
- **EventBus.close() event-loss window.** Events published after `bus.close()` are silently dropped by the bus itself (`event_bus.ts:37 — if (this.closed) return;`). The brain log writer's close-before-bus-close ordering avoids this for the writer's own perspective. Surfaced as an unfiled sibling-bug candidate in the analysis (weak evidence; no current incident signal).
- **Pattern precedent established at n=2.** Phase 14.1 introduces the second persistent EventBus subscriber (after SSE's iterator, which is ephemeral, not actually persistent — so this is really n=1 for the persistent-subscriber pattern). If a third persistent subscriber appears (e.g., a webhook-relay), the `subscribe()` return-thunk plus a `close()` method is the established shape; no `EventBus.subscribePersistent()` helper has been added yet (deferred per Refactor-Forward agent's own defer-with-reason; speculative at n=1).
- **Pattern precedent for n=3 ops adopting "settle resolved context first" / "persistent subscriber" / "JSONL writer with prune-at-boot."** Phase 12.1 (discover dedup) + Phase 13.1 (plan preamble) instantiated "settle resolved context first" — model-output structuring. Phase 14.1 instantiates "JSONL writer with prune-at-boot" — same shape as `RunLogWriter`. If a third JSONL writer appears, a shared `JsonlAppender` base class extraction is warranted (deferred for this phase per Refactor-Forward's own analysis).
