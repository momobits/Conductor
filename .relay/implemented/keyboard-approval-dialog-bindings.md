# Shared approval-dialog keybindings (Phase 17 #42)

## Summary

*Resolved: 2026-05-16*

- **Goal:** extract three near-duplicate transition-approval dialogs (in `board_dnd.ts`, `card_detail.ts`, plus the freshly-exported one consumed by Phase 25.2's `board_keys.ts`) into a shared helper at `src/ui/lib/dialog.ts` with first-class keyboard bindings (`Enter`/`Y` approve, `Esc`/`N` cancel, native Tab focus trap, Approve auto-focused). ## Caveats

- **`Enter`-always-approves UX choice (per spec, not a defect).** The new helper's keydown handler intercepts `Enter` regardless of which button is currently focused (and same for `Y`/`N`). If an operator `Tab`s to Cancel and presses `Enter` expecting the standard focused-button-activation pattern, they'll get Approve instead. This matches the spec verbatim (`Enter — Approve. Identical to clicking`) and is defensible — `Y`/`N` are the dedicated explicit shortcuts and `Enter` is bound to "primary action regardless of focus". An optional one-line refinement (only intercept `Enter` when no button is focused) is available if manual smoke surfaces user confusion. Surfaced in adversarial review as a LOW informational note; not required for this resolution.
- **`Phase \d+` references in code comments are out of scope.** The Step 5 sweep flagged 16 matches in source code comments (file headers, JSDoc, `//` notes including `lib/dialog.ts:12` which explicitly references "Phase 5/Phase 6" as meta-context for why the helper exists). Issue #35 was about leaked phase numbers in user-facing text (`innerHTML`/`textContent`), not source-code annotations. The plan and the issue's own footer treated code comments as out of scope.
- **`board_dnd.ts` cleanup advance:** the dead `escape` helper (previously only used by the deleted local `confirmTransition`) was removed in Step 3. `noUnusedLocals` is not enabled in `tsconfig.ui.json`, so leaving it wouldn't have broken the build — but cleanup keeps the file lean.
- **`card_detail.ts` `escape` helper deliberately preserved.** Verified at impl time the helper is referenced at `:75,78` (h3 title + button text) and inside `fmtFrontmatter` (`:43-50`). Deletion would have been a regression. Step 4's plan explicitly noted "KEEP local `escape`".
- **Manual smoke not exercised in browser this session.** The verification report's manual-smoke matrix is documented; operator validation deferred to session-end or next session.
